{% load static %} {% comment %} The launch screen the installed app shows while it boots. It exists because the operating system's own splash ends the moment the document starts painting, which is well before the shell is usable — the app appeared to flash a half-drawn page. This overlay continues that splash: same navy as the manifest's `background_color` and the icon surround, so the handover from the OS screen to this one is invisible and the launch reads as one motion rather than two. The choreography tells one small story — the logo is a pebble dropped into still water: 0.0s the logo falls in from above, accelerating; 0.8s it lands with a bob, and the impact throws a single splash ring; 1.6s a rotating loading arc fades in around it and keeps turning while the app boots, shedding a slow ripple with every pass — the ripples begin at the arc's own radius, so the turning ring reads as what is stirring the water; 5.0s the arc throws one last ring outward and the overlay is masked away behind it, so the final ripple is what uncovers the app. Standalone only, and once per launch. In a browser tab there is no OS splash to continue, and an overlay there would just be a delay; `sessionStorage` keeps it to the first document of a session so in-app navigation never replays it. The markup and its critical CSS are inline on purpose. A launch screen that waits for a stylesheet is not a launch screen — it has to paint on the first frame, before main.css has been fetched. {% endcomment %}
