{% load static %} {% comment %} The launch screen the installed app shows while it boots. It exists because the operating system's own splash ends the moment the document starts painting, which is well before the shell is usable — the app appeared to flash a half-drawn page. This overlay continues that splash: same navy as the manifest's `background_color` and the icon surround, so the handover from the OS screen to this one is invisible and the launch reads as one motion rather than two. Standalone only, and once per launch. In a browser tab there is no OS splash to continue, and an overlay there would just be a delay; `sessionStorage` keeps it to the first document of a session so in-app navigation never replays it. The markup and its critical CSS are inline on purpose. A launch screen that waits for a stylesheet is not a launch screen — it has to paint on the first frame, before main.css has been fetched. {% endcomment %}
