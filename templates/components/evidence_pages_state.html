{% comment %} The pages of one evidence form (owner, 2026-09-26: "the users can just take a photo or photos and confirm Upload ... allow multiple uploads and merge them into one file"). Included as a form's x-data: `x-data="{% include ... %}"`. Every photo taken and file chosen joins one list, in the order added, and each can be removed. The list is written into the form's named file input (x-ref="mainInput", `multiple`), so the ordinary submit (and the field outbox, which serialises the form as it stands) carries every page. The server checks each page and joins them into one PDF with exactly those pages (apps/evidence/pages.py). The camera and picker inputs are emptied after each pick, so the next photo fires `change` again. A browser without the DataTransfer constructor keeps the last pick only: one page, as before. A phone photo is 3-5 MB and 4000 px across; the page it becomes is A4 at 150 DPI (1240 x 1754), so it is sent at 2000 px on the long side: a fraction of the data over a field connection and in the outbox. The browser draws it upright (EXIF orientation applies by default), on white. Any failure sends the original.
