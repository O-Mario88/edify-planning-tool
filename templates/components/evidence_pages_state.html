{% comment %} The pages of one evidence form (owner, 2026-09-26: "the users can just take a photo or photos and confirm Upload ... allow multiple uploads and merge them into one file"). Included as a form's x-data: `x-data="{% include ... %}"`. Every photo taken and file chosen joins one list, in the order added, and each can be removed. The list is written into the form's named file input (x-ref="mainInput", `multiple`), so the ordinary submit (and the field outbox, which serialises the form as it stands) carries every page. The server checks each page and joins them into one PDF with exactly those pages (apps/evidence/pages.py). While a photo is being prepared it dispatches `evidence-pages-busy` (true, then false), so the form can hold its Submit until every page is in. The camera and picker inputs are emptied after each pick, so the next photo fires `change` again. A browser without the DataTransfer constructor keeps the last pick only: one page, as before. A phone photo is 3-5 MB and 4000 px across; the page it becomes is A4 at 150 DPI (1240 x 1754), so it is sent at 2000 px on the long side: a fraction of the data over a field connection and in the outbox. The browser draws it upright (EXIF orientation applies by default), on white. Any failure sends the original. A form that is already uploaded (`held`, set by the drawer) takes a file only as another page of it (owner, 2026-10-14: "ask the partner if it is a different page from the one they have uploaded if they say yes then allow if they say no then reject the second upload"). Files picked while `held` wait on that answer: `answer` is 'yes' once the partner says it is a different page, and saying it is the same page empties the list. `asking` is true while the question is open, so the form can hold its Submit.
