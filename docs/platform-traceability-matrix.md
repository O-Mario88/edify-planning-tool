## Requirement sets this matrix does not cover

- **Approved product extensions GAP-01..GAP-16** — The list exists only as prose in docs/release-readiness-2026-08-25.md, which names three of the sixteen (GAP-02, GAP-10, GAP-15) and summarises the rest. There is no machine-readable statement of the other thirteen anywhere in the repository, so they cannot be traced without first being written down. That is a product-owner deliverable, not an engineering one.
- **Role x page authorisation requirements** — Already traced, by a different artefact and a stronger method: docs/platform-permission-matrix.json enumerates every guarded route against every role from the RBAC tables themselves, which is exhaustive rather than execution-derived. Reproducing it here would add a second source of truth for the same question.
- **Metric definitions** — apps/core/metrics/registry.py already carries per-metric traceability as required fields -- owning service, source models, owner page, roles, drill-down and refresh events -- and registry.check() verifies the service paths resolve. This matrix joins to it rather than restating it.
